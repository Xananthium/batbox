The new cold-batch failure lowers the priority of a warm-prefix-only explanation. A precise future state/batch discriminator is to hold MTP2, original weights, full 200k context and sampling fixed, and compare the exact worker/seed alone against the same worker decoding during a large cold prefill, using new salts and counter-confirmed zero hits in both cases. Repeat after draining without restarting; record output validity, first-loop position and batch composition, not only aggregate speed. Failure only with overlapping prefill would focus the investigation on mixed execution; failure persisting after draining would support persistent process state. A subsequent same-process warm-versus-cold comparison can test whether reuse increases risk. The actual OpenAI chat-completions endpoint [accepts cache_salt](/home/isnotreal/vllm-env/lib/python3.12/site-packages/vllm/entrypoints/openai/chat_completion/protocol.py:485), so prompt bytes can stay unchanged. A cache-disabling restart would reintroduce the process-state confound. These are proposed discriminators, not additional tests run during restoration; a separate sampler sweep would need its own controlled comparison and cannot assume a sampling cause.

**Separate latency follow-up: mixed-batch TQ dispatch is confirmed; its performance impact is unmeasured.** MRV2 [takes the batch maximum scheduled query length](/home/isnotreal/vllm-env/lib/python3.12/site-packages/vllm/v1/worker/gpu/model_states/default.py:193), [passes it into every attention group's metadata](/home/isnotreal/vllm-env/lib/python3.12/site-packages/vllm/v1/worker/gpu/attn_utils.py:532), and the [TQ unified branch processes the entire batch before returning](/home/isnotreal/vllm-env/lib/python3.12/site-packages/vllm/v1/attention/backends/turboquant_attn.py:595). It bypasses the older mixed-batch split below line 625. The unified launcher sets [is_prefill_like when max_query_len > 4](/home/isnotreal/vllm-env/lib/python3.12/site-packages/vllm/v1/attention/ops/turboquant_soa/triton_turboquant_unified_attention.py:1053), then [selects 3D only when that flag is false](/home/isnotreal/vllm-env/lib/python3.12/site-packages/vllm/v1/attention/ops/turboquant_soa/triton_turboquant_unified_attention.py:1144). Consequently, a three-token MTP2 verification query uses unsplit 2D attention when co-batched with a large prefill, whereas it uses split-KV 3D alone. Full-attention TQ layers scan the long context; sliding layers remain window bounded.

Reusing the old split is not a safe one-line change. The [TQ builder keeps decode_threshold=1](/home/isnotreal/vllm-env/lib/python3.12/site-packages/vllm/v1/attention/backends/turboquant_attn.py:237) through `supports_spec_as_decode=False`; the [split helper](/home/isnotreal/vllm-env/lib/python3.12/site-packages/vllm/v1/attention/backends/utils.py:845) therefore classifies a leading q=3 row as prefill. Its decode convenience path [assumes one token per request and synthesizes consecutive query offsets](/home/isnotreal/vllm-env/lib/python3.12/site-packages/vllm/v1/attention/ops/turboquant_soa/triton_turboquant_unified_attention.py:1343). Simply raising the threshold and entering that path would lose MTP query boundaries.

A minimal future candidate is unified-only subgroup dispatch: retain the existing store once, send the leading short-query rows through the same unified launcher with their real query offsets and a subgroup maximum, and send the remaining rows through it with rebased offsets. Preserve output slices, block-table strides, sequence lengths, sliding windows, sinks and sliced multimodal-prefix metadata. Keep pure-batch graph paths and native-layer attention unchanged; avoid globally changing legacy decode classification. This is a proposed experiment, not an implemented fix. It still completes the entire mixed model forward before sampling, so it cannot emit decode tokens ahead of prefill work. Large prefill projection, MLP and native-attention costs remain; the source does not establish this dispatch as the dominant latency cause.

Meaningful future GPU validation would compare full mixed attention/step time for q=1 and q=3 alongside a prefill within the same 4096-token budget, at 29k–96k contexts, using both head dimensions and the actual SoA page strides. Check all-row finiteness and numerical agreement against dequantized reference attention, including sliding-window/block boundaries and reordered request rows. Then compare per-request inter-token p50/p95/p99, prefill time and throughput on the same captured mixed workload, plus pure-decode graph regression controls. An isolated q=3 kernel speedup is insufficient. No implementation or GPU validation was performed in this review.
